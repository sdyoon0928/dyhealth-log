> 바쁜 직장인이 매일의 건강 수치를 던져 넣기만 하면, 서버가 알아서 상태를 분류하고 위험 신호를 짚어주는 개인 건강 기록 API.

## 1. 개요

### 1.1 한 줄 정의

매일의 건강 수치(몸무게·키·혈압·혈당)를 기록하면, 서버가 **BMI를 자동 계산하고 건강 상태를 분류**하며, 위험 항목에 **경고를 생성**하고, 쌓인 데이터로 **통계**를 제공하는 REST API.

### 1.2 해결하려는 문제

건강검진 수치를 받아도 "이 숫자가 정상인지" 비전문가는 판단하기 어렵다. 측정값을 입력하는 순간 분류·경고가 함께 나와야 의미가 생긴다. 이 API는 **원본 저장과 해석을 한 번의 요청으로** 끝낸다.

### 1.3 목표 사용자

- 자신의 건강 수치를 꾸준히 기록하려는 개인
- 수치의 정상/위험 여부를 즉시 확인하고 싶은 비전문가

### 1.4 학습 목표 (과제 관점)

FastAPI로 REST API 설계, Pydantic 검증, 조건 분기 로직, 데이터 영속성, Docker 실행까지 하나의 흐름으로 경험한다. 건강 분류 기준은 학습용으로 단순화한 값이며 의학적 진단이 아니다.

---

## 2. 핵심 동작 흐름

```
사용자가 건강 수치를 POST로 전송
        │
        ▼
서버가 저장 + BMI 계산 + 혈압/혈당 분류 + 경고 생성
        │
        ▼
GET으로 기록·검색·통계를 JSON으로 응답
        │
        ▼
Docker 컨테이너로 실행 (/docs 에서 테스트)
```

## 3. 기능 요구사항

### 3.1 필수 엔드포인트

| # | 메서드 · 경로 | 동작 | 상태 |
|---|---|---|---|
| 1 | POST `/records` | 기록 추가. 저장 후 BMI·분류·경고 계산해 응답 | 필수 |
| 2 | GET `/records` | 전체 기록 조회 (총 개수 포함) | 필수 |
| 3 | GET `/records/{id}` | 단건 조회. 없으면 404 | 필수 |
| 4 | PUT `/records/{id}` | 기록 수정 | 필수 |
| 5 | DELETE `/records/{id}` | 기록 삭제 | 필수 |
| 6 | GET `/search` | 날짜 범위(start, end)로 검색 | 필수 |
| 7 | GET `/stats` | 평균 체중 등 통계 반환 | 필수 |

### 3.2 공통 요구사항

- 요청 본문은 **Pydantic 모델로 검증**한다.
- 기록은 **파일에 저장**해 서버를 재시작해도 유지된다.
- `/docs`(자동 문서)에서 모든 기능을 테스트할 수 있다.
- 실행 중 예외로 서버가 죽지 않는다.

### 3.3 선택 기능 (가점 · 본 프로젝트 구현 범위)

| 기능 | 설명 | 구현 여부 |
|---|---|---|
| 사용자 구분 | user를 추가해 사용자별 기록 분리 | ✅ 구현 |
| 간단 화면 | HTML 한 페이지로 기록 입력·조회 | ✅ 구현 |
| 클라우드 배포 | 공인 IP로 접속 가능 | ⬜ 예정 (Lightsail) |
| 주간 리포트 | 최근 7일 평균, 지난주 대비 변화 | ⬜ 미정 |
| 목표 관리 | 목표 체중/혈압 대비 달성률 | ⬜ 미정 |

## 4. 데이터 규격

### 4.1 기록 필드 (입력)

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| date | str (YYYY-MM-DD) | 필수 | 측정일 |
| weight | float | 필수 | 몸무게 (kg) |
| height | float | 필수 | 키 (cm) |
| systolic | int | 필수 | 수축기 혈압 |
| diastolic | int | 필수 | 이완기 혈압 |
| blood_sugar | int | 필수 | 공복 혈당 (mg/dL) |
| steps | int | 선택 | 걸음 수 |
| sleep_hours | float | 선택 | 수면 시간 |
| memo | str | 선택 | 메모 |

### 4.2 응답에 추가되는 계산 필드

원본 필드에 더해 서버가 계산해 응답한다. **저장하지 않고 응답 시점에 계산**한다(기준 변경 시 과거 데이터가 틀려지지 않도록).

| 필드 | 타입 | 설명 |
|---|---|---|
| bmi | float | 몸무게 ÷ (키(m))² |
| bmi_category | str | 저체중 / 정상 / 과체중 / 비만 |
| bp_category | str | 정상 / 주의 / 고혈압 |
| sugar_category | str | 정상 / 공복혈당장애 / 당뇨 의심 |
| warnings | list[str] | 위험 항목 경고 (없으면 `[]`) |

## 5. 분류 기준 (비즈니스 로직)

### 5.1 BMI

`BMI = 몸무게(kg) ÷ (키(m) × 키(m))` — 키가 cm이면 100으로 나눠 m로 변환.

| 구간 | 분류 |
|---|---|
| 18.5 미만 | 저체중 |
| 18.5 ~ 22.9 | 정상 |
| 23 ~ 24.9 | 과체중 |
| 25 이상 | 비만 |

### 5.2 혈압

| 조건 | 분류 |
|---|---|
| 수축기 < 120 **그리고** 이완기 < 80 | 정상 |
| 120~139 **또는** 80~89 | 주의 |
| 수축기 ≥ 140 **또는** 이완기 ≥ 90 | 고혈압 |

> 구현 시 고혈압 → 정상 → 주의 순으로 검사한다. 정상을 먼저 판정하면 한쪽만 높은 값이 잘못 분류된다.

### 5.3 공복혈당

| 구간 | 분류 |
|---|---|
| 100 미만 | 정상 |
| 100 ~ 125 | 공복혈당장애 |
| 126 이상 | 당뇨 의심 |

### 5.4 경고(warnings) 규칙

- BMI가 **비만**이면 경고 추가
- 혈압이 **고혈압**이면 경고 추가
- 혈당이 **당뇨 의심**이면 경고 추가
- 해당 없으면 빈 목록 `[]`

## 6. 통계 (`GET /stats`)

전체 기록을 집계해 반환한다. 최소 요구는 평균 체중이며, 아래 항목을 함께 제공한다.

| 항목 | 설명 |
|---|---|
| count | 총 기록 수 |
| avg_weight | 평균 몸무게 |
| avg_bmi | 평균 BMI |
| avg_systolic / avg_diastolic | 평균 혈압 |
| avg_blood_sugar | 평균 공복혈당 |

> 기록이 0건이면 평균은 null 또는 0으로 처리하고 오류를 내지 않는다.

## 7. 응답 코드 정책

| 코드 | 상황 |
|---|---|
| 200 | 성공 (생성·삭제 포함, 일관성 위해 통일) |
| 400 | 논리적으로 잘못된 요청 (시작일 > 종료일 등) |
| 404 | 대상 없음 (없는 id 조회) |
| 409 | 중복 충돌 (이메일, 같은 날짜 기록) |
| 422 | 값 검증 실패 (미래 날짜, 수축기 ≤ 이완기, 범위 초과) |

## 10. 미결정 · 위험 사항 (제출 전 반드시 확정)

과제 명세와 현재 구현 사이에 차이가 있어, 제출 전 다음을 결정해야 한다.

### 10.1 저장 방식 (가장 중요)

- **명세 요구:** JSON 파일(data.json) 저장
- **현재 구현:** PostgreSQL

> **선택지 A** — 명세대로 JSON 파일로 변경. 요구사항 100% 충족.
> **선택지 B** — PostgreSQL 유지. README에 "파일 저장보다 발전된 영속성 방식을 채택"임을 명시. 채점 기준이 엄격하면 감점 위험 존재.

### 10.2 엔드포인트 경로 · 메서드

- 명세는 `/records` 경로와 **PUT** 수정을 요구한다.
- 현재는 `/logs` 계열 경로와 **PATCH**를 사용한다.
- 최소한 `/records`, PUT 명세를 만족하는 라우트를 **추가**하거나 이름을 맞춘다.

### 10.3 누락된 필수 기능

- `GET /search`, `GET /stats`는 **필수인데 아직 없다. 반드시 구현**한다.
